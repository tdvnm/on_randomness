\section{The problem}

\begin{frame}{Two meanings of ``random''}
  \begin{enumerate}
    \item A sequence \emph{looks} random. Half zeros, half ones, runs of
          the right length, nothing repeats. \hfill (statistics)
    \item A sequence \emph{is} unpredictable. Knowing everything else,
          you still cannot guess the next bit. \hfill (cryptography)
  \end{enumerate}
  \pause
  \medskip
  These come apart in both directions.
  \begin{itemize}
    \item A sequence can pass every test and be fully predictable.
    \item A ciphertext can look like noise and still leak the message.
  \end{itemize}
  \pause
  \medskip
  Cryptography needs the second kind. Statistics can only check the
  first. The project is about the gap between them.
\end{frame}

\begin{frame}{Problem statement}
  \begin{block}{Main question}
    If the randomness used to make an encryption key gets worse, how
    much more does the ciphertext reveal about the message?
  \end{block}
  \medskip
  Two smaller questions sit on either side of it.
  \begin{enumerate}
    \item How do you test, with statistics, whether a sequence behaves
          randomly? What do those tests miss?
    \item If a sequence passes the tests, is it safe to use as a key?
  \end{enumerate}
  \pause
  \medskip
  I expect the answer to the last one is \emph{no}. The point of the
  project is to show why, with a derivation and a simulation for each
  claim, using the tools from this course.
\end{frame}

\begin{frame}{Why anyone should care}
  Every key, nonce and session token is a number an attacker must not
  guess. When the randomness behind it is bad, the cipher does not
  matter.
  \begin{itemize}
    \item \textbf{Debian OpenSSL, 2006--08.} A patch cut the seeding
          down to the process ID. Every key made in two years came from
          a pool of $32{,}767$.
    \item \textbf{Sony PlayStation~3, 2010.} The same ``random'' number
          was reused in every signature. That gave away the private
          key.
  \end{itemize}
  \pause
  \medskip
  Both systems used sound ciphers. Nothing in the output gave the
  failure away. The keys and signatures looked fine. The failure was in
  the probability, not the algorithm.
  \medskip

  That is a failure you can only see if you model the randomness
  itself. This project does that on systems small enough to work out by
  hand.
\end{frame}

\begin{frame}{Why small systems}
  I do not use AES or RSA. I use coin flips, a linear congruential
  generator, a Caesar cipher, XOR and the one-time pad.
  \medskip
  \begin{itemize}
    \item Every one of them has a joint distribution I can write down.
    \item So every simulation has an exact answer to be checked against.
    \item The lessons transfer: Shannon's definition of secrecy does not
          care how big the cipher is.
  \end{itemize}
  \medskip
  The plan is always the same. Derive the number. Simulate the system.
  See that they agree.
\end{frame}

\section{The model}

\begin{frame}{One project, two models}
  \begin{columns}[T]
    \begin{column}{0.48\textwidth}
      \textbf{Model I: a bit source}\\
      \emph{Is this sequence random?}
      \medskip
      \begin{itemize}
        \item A hypothesis test.
        \item Null: the bits are i.i.d.\ fair coins.
        \item Alternatives: a biased coin, a person, a deterministic
              generator.
        \item Output: a $p$-value per test.
      \end{itemize}
    \end{column}
    \begin{column}{0.48\textwidth}
      \textbf{Model II: a cipher}\\
      \emph{What does the ciphertext give away?}
      \medskip
      \begin{itemize}
        \item A joint distribution of three random variables
              $\msg, \key, \ctxt$.
        \item Secrecy is a statement about
              $\Prob{\msg = m \mid \ctxt = c}$.
        \item Leakage is a number, $\MI{\msg}{\ctxt}$.
        \item Output: an exact curve and a simulated one.
      \end{itemize}
    \end{column}
  \end{columns}
  \medskip
  Model I is the first half of the project. Model II is the second. The
  last part joins them: a source that passes Model I and fails as a key
  in Model II.
\end{frame}

% ---------------------------------------------------------------------
\subsection{Model I: a bit source}

\begin{frame}{Model I: the random variables}
  A sequence is $B_1, B_2, \dots, B_n$ with each $B_i \in \bits$.
  \medskip
  \begin{block}{Null hypothesis $H_0$ (an ideal source)}
    $B_1, \dots, B_n$ i.i.d.\ $\Bern(\tfrac12)$.
    Every one of the $2^n$ sequences has probability $2^{-n}$.
  \end{block}
  \pause
  \medskip
  \textbf{Alternatives}, each a distribution I can simulate from:
  \begin{itemize}
    \item \textbf{Biased coin.} $B_i$ i.i.d.\ $\Bern(p)$, $p \ne \tfrac12$.
    \item \textbf{A person.} A two-state Markov chain on $\bits$ with
          switching probability $s = \Prob{B_{i+1} \ne B_i \mid B_i}$.
          People who try to ``be random'' have $s > \tfrac12$: they
          avoid long runs.
    \item \textbf{A generator.} $X_{i+1} = (aX_i + c) \bmod m$, output
          one bit of $X_i$. Not random at all: given $X_0$ the
          sequence is fixed.
  \end{itemize}
  \pause
  \medskip
  Each test picks a statistic $T$, works out the law of $T$ under
  $H_0$, and reports the $p$-value
  $\Prob{T \text{ at least as extreme as } t_{\mathrm{obs}} \mid H_0}$.
\end{frame}

\begin{frame}{Model I: frequency and runs}
  \textbf{Frequency.} $X = \sum_{i=1}^{n} B_i$, the number of ones.
  Under $H_0$
  \[
    X \sim \Bin(n, \tfrac12),\qquad \Ex{X} = \tfrac n2,\qquad
    \Var{X} = \tfrac n4,
  \]
  and the CLT gives $(X - n/2)/\sqrt{n/4} \approx \mathcal{N}(0,1)$.
  Catches the biased coin. Misses the person.
  \pause
  \medskip

  \textbf{Runs.} Let $D_i = B_i \xor B_{i+1}$ mark a switch, and
  $R = 1 + \sum_{i=1}^{n-1} D_i$ count the runs.
  The map $(B_1,\dots,B_n) \mapsto (B_1, D_1, \dots, D_{n-1})$ is a
  bijection of $\bits^n$, so under $H_0$ the $D_i$ are again i.i.d.\
  $\Bern(\tfrac12)$ and
  \[
    R - 1 \sim \Bin(n-1, \tfrac12).
  \]
  For the person, $D_i$ are i.i.d.\ $\Bern(s)$ instead, so
  $R - 1 \sim \Bin(n-1, s)$. Same test statistic, different law, and
  the test sees it.
\end{frame}

\begin{frame}{Model I: pairs, lags and entropy}
  \textbf{Chi-square on pairs.} Cut the sequence into $n/2$ blocks of
  two bits. $N_{ab}$ counts the block $ab$. Under $H_0$
  \[
    (N_{00}, N_{01}, N_{10}, N_{11}) \sim \Mult(\tfrac n2;\
      \tfrac14, \tfrac14, \tfrac14, \tfrac14),
    \qquad
    Q = \sum_{ab} \frac{(N_{ab} - n/8)^2}{n/8} \approx \chi^2_3 .
  \]
  \pause
  \textbf{Autocorrelation at lag $k$.}
  $A_k = \sum_{i=1}^{n-k} \Ind{B_i \ne B_{i+k}}$.
  The functionals $B_i \xor B_{i+k}$ are linearly independent over
  $\mathrm{GF}(2)$, so under $H_0$ they are i.i.d.\ $\Bern(\tfrac12)$ and
  $A_k \sim \Bin(n-k, \tfrac12)$ exactly.
  \pause
  \medskip

  \textbf{Entropy.} Not a test statistic but a measure of how
  unpredictable the source is.
  \[
    \Ent{B} = -\sum_{b \in \bits} \Prob{B = b}\log_2 \Prob{B = b}
            = h(p) = -p\log_2 p - (1-p)\log_2(1-p).
  \]
  It is $1$ bit only when $p = \tfrac12$. For $p = 0.9$ it is
  $0.47$ bits. I estimate it by plugging in the observed frequency.
\end{frame}

\begin{frame}{Model I: summary of the random variables}
  \begin{center}\footnotesize
    \begin{tabular}{@{}llll@{}}
      \toprule
      Variable & Definition & Law under $H_0$ & Test \\
      \midrule
      $B_i$ & one bit & $\Bern(\tfrac12)$, independent & --- \\
      $X$ & $\sum_{i=1}^{n} B_i$ & $\Bin(n,\tfrac12)$ & frequency \\
      $R$ & $1+\sum_{i=1}^{n-1}\Ind{B_i\ne B_{i+1}}$
          & $R-1 \sim \Bin(n-1,\tfrac12)$ & runs \\
      $N_{ab}$ & count of block $ab$ among $n/2$
               & $\Mult(\tfrac n2;\tfrac14,\dots,\tfrac14)$ & chi-square \\
      $Q$ & $\sum_{ab}(N_{ab}-n/8)^2/(n/8)$ & $\approx\chi^2_3$ & chi-square \\
      $A_k$ & $\sum_{i=1}^{n-k}\Ind{B_i\ne B_{i+k}}$ & $\Bin(n-k,\tfrac12)$ & autocorrelation \\
      $\Ent{B}$ & $h(p)$ & $=1$ bit iff $p=\tfrac12$ & entropy \\
      $P$ & $p$-value of any test & $\Unif(0,1)$ & calibration \\
      \bottomrule
    \end{tabular}
  \end{center}
  \medskip
  The last row is how I check the tests themselves. If a test is right,
  its $p$-value on a truly fair source is uniform on $[0,1]$. I will
  run each test on thousands of fair sequences and look at the
  histogram before I trust it on anything else.
\end{frame}

\subsection{Model II: a cipher}

\begin{frame}{Model II: the random variables}
  Three random variables on $\bits^n$:
  \[
    \msg \text{ (message)}, \qquad \key \text{ (key)}, \qquad
    \ctxt = \msg \xor \key \text{ (ciphertext)}.
  \]
  \begin{block}{Assumption}
    $\key$ is independent of $\msg$. The attacker sees $\ctxt$, knows
    the cipher, knows $\Prob{\msg = m}$ and $\Prob{\key = k}$, and does
    not know $\key$.
  \end{block}
  \pause
  \medskip
  Because $\xor$ is its own inverse, $\{\msg = m, \ctxt = c\}$ is the
  same event as $\{\msg = m, \key = m \xor c\}$. So the whole joint law
  is
  \[
    \Prob{\msg = m, \ctxt = c} = \Prob{\msg = m}\,\Prob{\key = m \xor c},
  \]
  and by the law of total probability
  \[
    \Prob{\ctxt = c} = \sum_{m} \Prob{\msg = m}\,\Prob{\key = m \xor c}.
  \]
  Everything I compute about the cipher comes from these two lines.
\end{frame}

\begin{frame}{Model II: the distributions I use}
  I take $n = 2$, so there are four messages, four keys, four
  ciphertexts, and every answer can be computed exactly.
  \begin{center}\footnotesize
    \begin{tabular}{@{}lll@{}}
      \toprule
      Variable & Distribution & Role \\
      \midrule
      $\msg$ & $\Prob{00,01,10,11} = (0.4,\,0.3,\,0.2,\,0.1)$;
               $\Ent{\msg} = 1.85$ bits & lopsided on purpose \\
      \addlinespace
      $\key$ & independent of $\msg$; one of & \\
      \quad A & $\Unif(\bits^2)$; $\Ent{\key} = 2$ bits & one-time pad \\
      \quad B & $\Prob{\key=00}=0.7$, the rest $0.1$ each;
                $\Ent{\key} = 1.36$ bits & one bad value \\
      \quad C & $K_1,K_2$ i.i.d.\ $\Bern(q)$, $q\in[0.5,0.95]$;
                $\Ent{\key}=2h(q)$ & the sweep \\
      \addlinespace
      $\ctxt$ & $\ctxt = \msg\xor\key$;\;
                $\Prob{\ctxt=c} = \sum_m \Prob{\msg=m}\Prob{\key=m\xor c}$
              & what the attacker sees \\
      \bottomrule
    \end{tabular}
  \end{center}
  \medskip
  The message is lopsided so that there is something to leak. If
  $\msg$ were uniform, every cipher would look perfect.
\end{frame}

\begin{frame}{Model II: what ``secure'' means}
  Shannon (1949): a cipher is \textbf{perfectly secret} if for every
  $m$ and $c$
  \[
    \Prob{\msg = m \mid \ctxt = c} = \Prob{\msg = m}.
  \]
  Seeing the ciphertext does not change what you believe about the
  message.
  \pause
  \medskip

  \textbf{The one-time pad has it.} With $\key$ uniform on $\bits^n$,
  \[
    \Prob{\ctxt = c \mid \msg = m} = \Prob{\key = m \xor c} = 2^{-n},
  \]
  which does not depend on $m$. Total probability gives
  $\Prob{\ctxt = c} = 2^{-n}$ too, and Bayes' rule gives
  \[
    \Prob{\msg = m \mid \ctxt = c}
      = \frac{2^{-n}\,\Prob{\msg = m}}{2^{-n}} = \Prob{\msg = m}.
  \]
  \pause
  \textbf{Any other key breaks it.} If $\Prob{\key = k}$ varies with
  $k$, then $\Prob{\ctxt = c \mid \msg = m}$ varies with $m$, and the
  ciphertext carries information. The next slide says how much.
\end{frame}

\begin{frame}{Model II: measuring the leak}
  Uncertainty before and after seeing the ciphertext:
  \[
    \Ent{\msg} = -\sum_m \Prob{\msg=m}\log_2\Prob{\msg=m},
    \qquad
    \CEnt{\msg}{\ctxt} = \sum_c \Prob{\ctxt=c}\,\Ent{\msg \mid \ctxt = c}.
  \]
  The difference is the mutual information, the number of bits that
  leaked:
  \[
    \MI{\msg}{\ctxt} = \Ent{\msg} - \CEnt{\msg}{\ctxt} \;\ge\; 0 .
  \]
  Perfect secrecy is the same thing as $\MI{\msg}{\ctxt} = 0$.
  \pause
  \medskip

  For this cipher there is a shortcut. Given $\msg$, the ciphertext is
  a shifted copy of the key, so $\CEnt{\ctxt}{\msg} = \Ent{\key}$ and
  \[
    \MI{\msg}{\ctxt} = \Ent{\ctxt} - \Ent{\key}
    \;\ge\; \Ent{\msg} - \Ent{\key}.
  \]
  The bound is Shannon's: a key with less entropy than the message
  must leak at least the difference. This is the curve I will test.
\end{frame}

\section{Research direction}

\begin{frame}{The chain I want to follow}
  \[
    \text{randomness} \;\to\; \text{uncertainty} \;\to\;
    \text{information} \;\to\; \text{secrecy}
  \]
  Four studies, one per link. Each has a claim, a derivation, a
  simulation, and a way to be wrong.
  \medskip
  \begin{enumerate}
    \item \textbf{Test the sources.} Which tests catch which failures?
    \item \textbf{Measure the ciphers.} How much does each one leak?
    \item \textbf{Degrade the key.} The main experiment: leakage as a
          function of key entropy.
    \item \textbf{Break a good-looking generator.} Pass every test,
          still predictable.
  \end{enumerate}
\end{frame}

\begin{frame}{Study 1: test the sources}
  \textbf{Sources.} Fair coin, biased coin ($p = 0.6$), human sequences
  (collected from classmates, $n \approx 100$ each), an LCG, the OS
  generator, Blum--Blum--Shub.
  \medskip

  \textbf{Method.} $1000$ sequences of $n = 1000$ bits per source (fewer
  for people). Run all five tests on each. Record $p$-values and
  the plug-in entropy. Fit $\hat s$ (switching probability) to the human
  data.
  \medskip

  \textbf{Claims.}
  \begin{itemize}
    \item The frequency test catches the biased coin and nothing else.
    \item The runs test catches people: $\hat s > \tfrac12$ and
          $R$ too large.
    \item The LCG, the OS generator and BBS pass all five.
  \end{itemize}
  \medskip

  \textbf{Wrong if} the human sequences look like fair coins under every
  test, or if the LCG fails a test. Either would change Study~4.
\end{frame}

\begin{frame}{Study 2: measure the ciphers}
  \textbf{Caesar.} Message is English text, key is a shift
  $\key \sim \Unif\{0,\dots,25\}$, so $\Ent{\key} = \log_2 26 = 4.7$ bits.
  Shannon's bound says $\MI{\msg}{\ctxt} \ge \Ent{\msg} - 4.7$ bits.
  For a paragraph of text, $\Ent{\msg}$ is hundreds of bits. Nearly all
  of it leaks. The letter histogram of the ciphertext is the plaintext's
  histogram, shifted.
  \medskip

  \textbf{XOR with a bad key.} Key from source B. Exact leakage
  $\MI{\msg}{\ctxt} = 0.59$ bits of the $1.85$ in the message.
  \medskip

  \textbf{One-time pad.} Key from source A. Exact leakage $0$.
  \medskip

  \textbf{Method.} Draw $N = 10^4$ pairs $(\msg, \ctxt)$, build the
  $4 \times 4$ table of counts, plug the frequencies into
  $\Ent{\msg} - \CEnt{\msg}{\ctxt}$. Compare with the exact value.
  \medskip

  \textbf{Something I already know will happen.} The plug-in estimate
  of $\MI{\msg}{\ctxt}$ is biased upward, by about
  $(|\mathcal M|-1)(|\mathcal C|-1)/(2N\ln 2) \approx 6\times10^{-4}$
  bits for $N = 10^4$. So the one-time pad will not read exactly zero.
  I will show the estimate falling towards zero as $N$ grows.
\end{frame}

  Fix the cipher. Fix the message. Only change the key source, with
  $K_1, K_2$ i.i.d.\ $\Bern(q)$ for $q = 0.50, 0.55, \dots, 0.95$.
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}

          \addlegendentry{$\Ent{\msg}$}
        \end{axis}
      \end{tikzpicture}
    \end{column}
    \begin{column}{0.48\textwidth}
      \small
      The exact curve, computed today from
      $\MI{\msg}{\ctxt} = \Ent{\ctxt} - \Ent{\key}$.
      \medskip

      At $q = 0.5$ the key is a one-time pad and nothing leaks. At
      $q = 0.95$ the key has $0.57$ bits of entropy and $1.30$ of the
      message's $1.85$ bits leak.
      \medskip

      \textbf{Method.} At each $q$, draw $N = 10^4$ pairs, estimate
      $\MI{\msg}{\ctxt}$ as in Study~2, repeat $50$ times for error
      bars. Plot the estimates on top of this curve, and again against
      $\Ent{\key}$.
      \medskip

      \textbf{Wrong if} the simulated points miss the curve by more than
      the error bars. That would mean a bug in the estimator or in my
      derivation, and either is worth finding.
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Study 4: break a good-looking generator}
  Back to the LCG from Study~1. It passed every test. Now use it as the
  key source for the cipher.
  \medskip

  \textbf{Claim.} For a real source
  $\CEnt{B_{n+1}}{B_1,\dots,B_n} = 1$ bit: the past says nothing about
  the next bit. For the LCG it is $0$ once the state is known, and the
  state can be recovered from a few outputs.
  \medskip

  \textbf{Method.}
  \begin{itemize}
    \item Recover $X_i$ from the output bits, then predict every later
          bit. Count how many outputs it takes.
    \item Encrypt with the LCG as key stream. Show that an attacker who
          sees a short prefix of the plaintext reads the rest.
    \item Contrast with Blum--Blum--Shub, where predicting the next bit
          is as hard as factoring. Same statistics, different
          unpredictability.
  \end{itemize}
  \medskip

  This is the slide the title is about. The LCG's output has entropy $1$
  bit per bit as far as the tests can tell, and $0$ bits per bit to
  someone who knows the state. Statistical randomness is a property of
  the output. Security is a property of what the attacker knows.
\end{frame}

\begin{frame}{What I expect, and what would surprise me}
  \begin{columns}[T]
    \begin{column}{0.48\textwidth}
      \textbf{Expected}
      \begin{itemize}
        \item Human sequences fail the runs test, pass the frequency
              test.
        \item Caesar leaks nearly all of $\Ent{\msg}$.
        \item One-time pad: $\MI{\msg}{\ctxt} \to 0$ as $N$ grows.
        \item Leakage rises as $\Ent{\key}$ falls, never below
              $\Ent{\msg} - \Ent{\key}$.
        \item The LCG passes five tests and is predictable from a
              handful of outputs.
      \end{itemize}
    \end{column}
    \begin{column}{0.48\textwidth}
      \textbf{Would surprise me}
      \begin{itemize}
        \item People who pass the runs test. Then I would look at the
              lag-$2$ autocorrelation.
        \item A simulated point below Shannon's bound. Impossible if
              the code is right, so it is a bug detector.
        \item A gap between simulation and the exact curve that does
              not shrink like $1/N$.
      \end{itemize}
      \medskip
      Every claim comes with a way to fail. That is what makes this a
      project and not a demonstration.
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Takeaway}
  \begin{center}
    \Large Good randomness is necessary for secrecy.\\[0.5em]
    Looking random is not enough to make something secure.
  \end{center}
  \bigskip
  \begin{center}
    \small
    Statistics tests the output. Security is about what the attacker
    knows. The project measures the distance between the two.
  \end{center}
\end{frame}
